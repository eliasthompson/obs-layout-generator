# AGENTS.md

TypeScript library, published to npm as `@eliasthompson/obs-layout-generator` (unscoped `obs-layout-generator` up to 1.1.0), that computes pixel rectangles for multi-participant OBS scene layouts. No runtime dependencies.

## Commands

- `npm run typecheck`: `tsc --noEmit`
- `npm run lint` / `npm run lint:fix`: ESLint with type-aware rules
- `npm run format` / `npm run format:check`: Prettier
- `npm run test` / `npm run test:coverage` / `npm run test:watch`: Vitest
- `npm run build`: tsdown, emits `dist/index.js` and `dist/index.d.ts`

Before finishing a change, run typecheck, lint, format check, test coverage, and build. All five must pass.

## Layout

- `src/constants/`, `src/lib/`, `src/types/`: source, one export group per file.
- `src/index.ts`: the only index file and the package's single entry point. When adding a file, add an `export *` line for it here (`export type *` for type-only files). Do not add per-directory index files.
- `src/lib/*.test.ts`: one test file beside each lib file. Coverage of `src/lib` is held at 100% for statements, branches, functions, and lines; code that tests cannot reach should be restructured rather than excluded.
- `dist/`: build output, git-ignored. Never edit it.

## Conventions

- Object keys and interface/type members are deliberately not sorted. Keep semantic orders like `x, y, width, height`, and list an object's keys in the same order as its type.
- In config files (tsconfig, tsdown, ESLint, Prettier, package.json `scripts`), keep keys alphabetical and do not add comments.
- Runtime and type readonly-ness must match. Freeze literal constants (`Object.freeze([...] as const)`), which makes both readonly. Leave derived values like `numericContentAspectRatios` unfrozen, since their types cannot be readonly literals.
- The layout model (main/side columns, main-column fallback order, side stacking, name placement, omitted regions) is documented in README.md. Update it whenever `generateLayout` behavior changes.
- Changes to `generateLayout` should not alter output for ordinary inputs unless intended. The snapshot test in `generateLayout.test.ts` guards this; update the snapshot (`npx vitest run -u`) only for intended changes, and say so.
- The `package.json` `exports`, `main`, `module`, and `types` fields are generated by tsdown. Do not edit them by hand.

## Commits

- [Conventional Commits](https://www.conventionalcommits.org/): `feat`, `fix`, `docs`, `refactor`, `build`, `ci`, or `chore`. A breaking change adds `!` after the type and a `BREAKING CHANGE:` footer saying what to change.
- The subject is one lowercase sentence in the imperative, with no period, saying what changes and, where it helps, why or how: `feat: keep side cameras no narrower than 9:16 by shortening them`.
- Add a body only when the subject cannot carry the change: a paragraph, or a list for several changes, wrapped at 120 columns.
- No trailers, such as `Co-Authored-By`, on any commit.
- A release is a commit of its own, `chore: release vX.Y.Z`, with no body. Bump with `npm version <major|minor|patch> --no-git-tag-version` (major for a breaking change since the last release, minor for a feature, patch otherwise), and tag the commit with an annotated `vX.Y.Z` tag of the same message. Pushing the tag runs `.github/workflows/publish.yml`, which publishes to npm and creates the GitHub release; it fails when the tag and package.json disagree.

## Toolchain constraints

- TypeScript is pinned to 6.x because typescript-eslint does not support 7.x yet. Do not upgrade it until it does.
- Do not use `baseUrl` in tsconfig; `paths` resolves relative to the tsconfig file.
- Keep the library platform-neutral: no Node built-ins or `@types/node` in `src`.
